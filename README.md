# gapu-chap-front — веб-клиент чата

React-клиент для бэкенда [gapu-chap](../gapu-chap): комнаты и личные диалоги, сообщения
в реальном времени через WebSocket, статус «онлайн», отметки «прочитано» и счётчики
непрочитанных, поиск по истории, панель модератора с блокировкой пользователей.

Архитектура — **Feature-Sliced Design (FSD)**.

## Запуск

```bash
nvm use                 # Node 24 из .nvmrc (нужен Node ≥ 20.19)
npm install
npm run dev             # http://localhost:5173
```

Бэкенд должен работать на `http://localhost:8081` (`make run` в репозитории бэкенда).
Другой адрес — через переменную `BACKEND_URL` (см. `.env.example`).

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с прокси на бэкенд |
| `npm run build` | проверка типов + production-сборка в `dist/` |
| `npm run typecheck` | только TypeScript |
| `npm run lint` | ESLint (включая правила хуков React) |
| `npm run lint:fsd` | [Steiger](https://github.com/feature-sliced/steiger) — проверка правил FSD |
| `npm test` | Vitest: юнит-тесты логики |

Production-сборка вместе с бэкендом и базой — одной командой из репозитория бэкенда:
`make up` → http://localhost:8080 (образ: `Dockerfile` + `nginx.conf` в этом репозитории).

### Почему нет CORS

В dev Vite проксирует `/api`, `/health` и `/ws` на бэкенд. Для браузера фронт и API живут
на одном origin, поэтому CORS не нужен. `changeOrigin` у прокси **выключен** намеренно:
WebSocket-библиотека бэкенда (`coder/websocket`) сверяет заголовок `Origin` с `Host`
и отклоняет чужие сайты (защита от Cross-Site WebSocket Hijacking). С выключенным
`changeOrigin` они совпадают.

В production то же делает nginx (`nginx.conf`): отдаёт `dist/`, проксирует `/api` и `/ws`
на Go-сервер и передаёт `Host` **вместе с портом** (`$http_host`, а не `$host`) — иначе
`Origin: http://localhost:8080` не совпадёт с `Host: localhost`, и бэкенд отклонит WebSocket.

## Архитектура: Feature-Sliced Design

Код разложен по **слоям**. Слой может импортировать только слои **ниже** себя:

```
app       → инициализация: провайдеры, роутинг, мост WebSocket → кеш, глобальные стили
pages     → страницы: login, register, chat, moderation, not-found
widgets   → крупные блоки страницы: sidebar, room-chat, members-panel
features  → действия пользователя: войти, создать комнату, отправить сообщение…
entities  → бизнес-сущности: viewer (сессия), user, room, message
shared    → без бизнес-смысла: http/ws-клиенты, UI-кит, утилиты, конфиг
```

Внутри слоя код делится на **слайсы** (`entities/room`, `features/leave-room`), а слайс —
на **сегменты** по назначению: `api` (запросы), `model` (состояние и логика),
`ui` (компоненты), `lib` (чистые функции).

Три правила, которые проверяют линтеры:

1. **Импорт только вниз.** `features` не знает про `widgets`, `entities` не знает про `features`.
2. **Слайсы одного слоя не импортируют друг друга.** Например, `entities/message` не знает про
   `entities/user`. Аватар автора в `MessageBubble` приходит слотом `avatar` из виджета.
3. **Вход в слайс — только через публичный API** (`index.ts`). Импорт вида
   `@/entities/room/model/cache` запрещён ESLint-правилом, только `@/entities/room`.

## Как это работает

### Серверное и клиентское состояние — раздельно

- **TanStack Query** хранит всё, что пришло с сервера: комнаты, участники, история.
  Он сам кеширует, дедуплицирует запросы и отменяет их через `AbortSignal`.
- **Zustand** хранит то, чего нет в REST: токен сессии, кто сейчас онлайн, всплывающие уведомления.

### Реальное время: один сокет, один «мост»

`shared/api/realtime.ts` — WebSocket-клиент:
- **одно соединение на вкладку**, токен в `?token=` (браузерный WebSocket не умеет заголовки);
- **переподключение** с экспоненциальной задержкой (1 с → 30 с) и случайным разбросом (jitter),
  чтобы после рестарта сервера клиенты не пришли все в одну миллисекунду;
- **помнит подписки** и повторяет `room.subscribe` после переподключения.

`app/realtime/RealtimeBridge` подписывает сокет на **все мои комнаты**, не только на открытую.
Иначе нельзя было бы считать непрочитанные в остальных. Затем `handle-event.ts` раскладывает
события по кешу:

| Событие | Что меняется |
|---|---|
| `message.new` | сообщение добавляется в историю (с дедупликацией по `id`), чужое даёт +1 непрочитанное |
| `message.read` | у участника сдвигается отметка; если это я из другой вкладки — счётчик обнуляется |
| `presence` | стор «онлайн» |
| `room.joined` | обновить «мои комнаты» — нас добавили (вступили с другой вкладки, с нами открыли диалог) |
| `room.left` / `room.deleted` | комната убирается из списка; если она открыта — переход на главную |
| `error` | всплывающее уведомление |

Кеш правится **точечно** (`setQueryData`): ради «+1 непрочитанное» список комнат не
перезапрашивается. После переподключения кеш сообщений инвалидируется: пока связи не было,
что-то могли пропустить.

### Отправка — через REST, получение — через WebSocket

Бэкенд принимает сообщение и так и так. Клиент отправляет через `POST /messages`: у HTTP есть
ответ на **конкретный** запрос (201 или ошибка). Поэтому при ошибке можно вернуть текст в поле.
У WebSocket ответы асинхронные, и событие `error` не скажет, к какому сообщению оно относится.
Остальные участники всё равно получают сообщение мгновенно, сервер рассылает его по WS.

### Лента сообщений

- История грузится страницами по 50 (`useInfiniteQuery` + курсор `before`), старые
  подгружаются при прокрутке вверх (`IntersectionObserver`).
- Контейнер прокрутки — `flex-direction: column-reverse`, сообщения в DOM лежат от новых к старым
  (так их и отдаёт сервер). Браузер сам держит ленту прижатой к низу, а подгрузка старых сверху
  **не сдвигает** то, что пользователь сейчас читает. Ручной математики со `scrollTop` нет.
- Сообщения одного автора подряд (в пределах 5 минут) группируются, между днями стоят
  разделители «Сегодня / Вчера / 12 октября».

### «Прочитано»

- Комната отмечается прочитанной до последнего сообщения, **когда пользователь его видит**:
  вкладка активна, окно в фокусе и лента прокручена вниз. Задержка 400 мс схлопывает пачку
  сообщений в один запрос.
- Счётчик обнуляется сразу (оптимистично), сервер подтверждает событием `message.read`.
- У своих сообщений: ✓ — доставлено, ✓✓ — прочитал хотя бы один участник
  (подсказка при наведении показывает, кто именно).
- При открытии комнаты появляется разделитель «Новые сообщения».

### Личные диалоги

Диалог для бэкенда — комната `kind: 'direct'`; в «моих комнатах» сервер отдаёт собеседника
(`peer`), и интерфейс показывает его имя и аватар с онлайн-статусом вместо служебного
названия (`getRoomTitle`). Написать можно из окна «Новый диалог» (поиск по имени),
из списка «В сети» и из панели участников. Сервер не создаст второй диалог с тем же человеком,
поэтому кнопку «Написать» можно нажимать сколько угодно.

### Поиск по истории

Панель поиска справа (кнопка 🔍 в шапке комнаты): запрос уходит после паузы в наборе
(debounce 300 мс), совпадения подсвечиваются. Подсветка строится как массив частей текста,
а не HTML, поэтому текст сообщения не может внедрить разметку. Клик по результату ставит
в адрес `?message=<id>`: лента догружает страницы истории, пока не дойдёт до сообщения,
прокручивает к нему и ненадолго подсвечивает. Ссылкой с таким адресом можно поделиться.

### Модерация

У модератора в шапке есть 🛡 — страница `/moderation`: поиск пользователей, бейджи
«модератор» и «заблокирован», кнопки блокировки. Скрытая кнопка — только удобство:
права проверяет сервер. Если заблокировали **вас**, приложение выходит сразу по любому
из сигналов: ответ `403 user is banned` или закрытие WebSocket с кодом `4003`. Клиент по этому
коду не пытается переподключиться.

### Сессия

- JWT хранится в `localStorage`. `uid`, `username` и `exp` читаются из payload токена
  без запроса к серверу. Подпись проверяет только сервер.
- Выход происходит автоматически ровно в момент истечения токена и при любом 401 от API.
- При выходе очищается весь кеш, чтобы данные одного пользователя не достались следующему.

Компромисс: токен в `localStorage` доступен JavaScript, поэтому XSS-уязвимость позволила бы
его украсть. Надёжнее cookie `HttpOnly`, но это потребует изменений на бэкенде.

## Тесты

- `shared/api/realtime.test.ts` — переподключение, повтор подписок, синхронизация комнат
  (на фейковом WebSocket и фейковых таймерах);
- `entities/*/model/cache.test.ts` — точечные обновления кеша: дедупликация сообщений,
  отметка «только вперёд», счётчики;
- `entities/message/lib/feed.test.ts` — группировка и разделители дней;
- `features/register/model/validate.test.ts` — валидация, совпадающая с серверной
  (в том числе лимит bcrypt 72 **байта**, а не символа);
- `shared/lib/*.test.ts` — плюрализация, форматирование дат, разбор JWT.
